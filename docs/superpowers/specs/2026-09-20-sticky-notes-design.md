# PwdBook 轻量便签设计

## 1. 背景与目标

PwdBook 新增一套本地优先的轻量便签能力。功能参考 Simple Sticky Notes 的高频体验，但首期明确收敛为：便签、清单、颜色、置顶、搜索、单层便签本、收藏与回收站。

便签属于保险库数据，使用现有会话密钥加密，并纳入现有备份、导入导出和同步流程。PwdBook 锁定时，所有桌面便签立即隐藏；解锁后恢复锁定前可见的便签。

## 2. 范围

### 2.1 首期功能

- 从主窗口侧栏底部工具箱进入便签，入口位于“剪切板”下方。
- 点击入口打开独立便签管理窗口；重复点击聚焦已有窗口。
- 创建、编辑、搜索、收藏、移动、隐藏和删除便签。
- 创建、重命名和删除单层便签本。
- 在普通文本与待办项之间混排，支持待办勾选和多级缩进。
- 将单个便签弹出为独立桌面窗口，并支持拖动、缩放和置顶。
- 每条便签选择一款预设颜色，颜色自动适配当前明暗模式与皮肤。
- 便签关闭时仅隐藏，可从管理窗口重新显示。
- 软删除、回收站恢复和彻底删除。
- 加密存储、备份、导入导出和同步。
- 中文和英文界面文案。

### 2.2 不在首期范围

- 提醒、闹钟和重复提醒。
- 标签、多层便签本或便签本嵌套。
- 任意富文本样式、图片、附件、超链接编辑器和 Markdown 渲染。
- 自由调节透明度、安装第三方主题或声音扩展。
- 打印、RTF 导出、社交分享和多便签合并。
- 便签内容在锁定状态下继续显示。

## 3. 用户体验

### 3.1 主入口

`VaultSidebar` 的工具箱弹出菜单在“剪切板”下方增加“便签”，使用 Lucide `StickyNote` 图标。该入口不改变密码库当前选择或主窗口三栏布局。

点击后：

1. 若管理窗口尚未创建，则创建并显示。
2. 若管理窗口已存在但被隐藏或遮挡，则恢复并聚焦。
3. 若保险库已锁定，则拒绝打开并保持所有便签窗口隐藏。

### 3.2 独立管理窗口

管理窗口采用双栏工作区：

- 左栏顶部：全部、收藏、回收站和单层便签本。
- 左栏主体：搜索、新建按钮和当前范围内的便签列表。
- 右栏：当前便签的标题、操作栏和块编辑器。

操作栏包含收藏、颜色、弹出到桌面、移动至便签本和删除。列表为空或未选中便签时展示贴合现有 UI 的空状态，不使用营销式说明区域。

管理窗口为唯一实例。它复用 PwdBook 的自定义标题栏、主题 token、窗口控制方式和中英文文案体系。经典皮肤保持克制的工作台风格；动森皮肤复用现有纸张色、描边和装饰语言。

### 3.3 桌面便签窗口

每条便签最多对应一个桌面窗口。窗口无系统边框，包含：

- 可拖动标题区域。
- 置顶、颜色、隐藏和更多操作。
- 与管理窗口一致的块编辑器。
- 自动保存状态，仅在失败或重试时突出显示。

关闭按钮只隐藏窗口，不删除便签。删除必须通过更多菜单或管理窗口执行，并进入回收站。

窗口位置、尺寸、置顶和显示状态按便签保存。启动或显示器配置变化后，若保存坐标不再可见，窗口移动至主显示器工作区内。锁定时记录当前可见集合并隐藏全部便签；本次应用会话内再次解锁后恢复该集合。

### 3.4 块编辑器

首期块类型：

- `text`：普通文本。
- `checklist`：可勾选的待办项。

两种块可混排。每个块拥有稳定 ID、文本、类型、缩进层级和待办状态。交互包括：

- `Enter` 在当前块后新增同类型块。
- 空块按 `Backspace` 与上一块合并或删除当前块。
- `Tab` / `Shift+Tab` 增加或减少缩进。
- 工具栏或快捷命令在文本块与待办块之间切换。
- 勾选父待办项时不级联修改子项；首期只保存各项自己的勾选状态。

编辑内容即时反映在窗口中，停止输入约 400 ms 后自动保存；窗口关闭、隐藏或失焦前刷新待保存内容。

### 3.5 颜色

提供少量经过设计的预设色，例如黄、绿、蓝、粉、紫和中性纸色。色板使用语义 ID，不直接将最终 CSS 色值写入数据。每个语义色在经典/动森及浅色/深色模式下有对应 token，确保正文、图标、边框和焦点态满足可读性要求。

## 4. 领域模型与数据库

### 4.1 `note_books`

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | UUID |
| `name_encrypted` | TEXT | 会话密钥加密的名称 |
| `sort_order` | INTEGER | 同级排序 |
| `created_at` | INTEGER | Unix ms |
| `updated_at` | INTEGER | Unix ms，LWW 合并依据 |
| `deleted_at` | INTEGER NULL | 同步删除墓碑所需的软删除时间 |

系统视图“全部、收藏、回收站”不是便签本记录。系统提供一个不可删除的默认便签本；导入旧数据或恢复缺失便签本的便签时归入默认便签本。

### 4.2 `notes`

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | UUID |
| `book_id` | TEXT | 所属便签本 |
| `title_encrypted` | TEXT | 加密标题 |
| `content_encrypted` | TEXT | 加密的版本化块 JSON |
| `color` | TEXT | 语义色 ID |
| `is_favorite` | INTEGER | 0/1 |
| `is_desktop_visible` | INTEGER | 0/1，正常运行时的显示意图 |
| `is_always_on_top` | INTEGER | 0/1 |
| `window_x` | INTEGER NULL | 桌面窗口坐标 |
| `window_y` | INTEGER NULL | 桌面窗口坐标 |
| `window_width` | INTEGER NULL | 桌面窗口宽度 |
| `window_height` | INTEGER NULL | 桌面窗口高度 |
| `created_at` | INTEGER | Unix ms |
| `updated_at` | INTEGER | Unix ms，LWW 合并依据 |
| `deleted_at` | INTEGER NULL | 回收站与同步墓碑 |

块内容整体加密并作为单个版本化 JSON 文档保存：

```json
{
  "version": 1,
  "blocks": [
    {
      "id": "uuid",
      "type": "checklist",
      "text": "完成发布说明",
      "indent": 0,
      "checked": false
    }
  ]
}
```

`text` 块的 `checked` 固定为 `false`。首期缩进范围为 0 到 4，读取和写入时统一规范化。使用整体 JSON 而非独立块表，可减少自动保存写入和同步实体数量，同时保留未来通过 `version` 迁移块结构的能力。

### 4.3 删除规则

- 删除便签写入 `deleted_at` 并关闭对应桌面窗口。
- 恢复便签清除 `deleted_at`；原便签本不存在时进入默认便签本。
- 彻底删除从数据库移除记录，并写入同步所需删除墓碑。
- 删除非空便签本前，用户必须选择将便签移动到目标便签本，或将其中便签一并移入回收站。

## 5. 架构与数据流

便签作为独立领域接入现有三层结构：

```text
管理窗口 / 桌面便签窗口
        -> preload typed API
        -> IPC 参数校验
        -> note service / note book service
        -> session service + vault crypto
        -> SQLite
```

建议模块边界：

- `noteService`：便签 CRUD、搜索、收藏、软删除、恢复和加解密。
- `noteBookService`：便签本 CRUD、排序和删除约束。
- `noteWindowService`：管理窗口唯一实例、桌面窗口映射、几何校正、置顶和锁定生命周期。
- 共享块模块：块 schema、规范化、快捷编辑纯函数和版本迁移。
- 渲染层 store/composable：当前筛选、选择、编辑草稿和自动保存状态。

所有窗口通过 IPC 访问数据，不直接接触数据库或会话密钥。主进程在数据变化后广播带实体 ID 和更新时间的 `notes:changed` 事件；各窗口按需重新读取实体。

### 5.1 自动保存与并发

- 编辑器维护本地草稿和服务器版本时间。
- 输入停止约 400 ms 后提交完整标题与块内容。
- 隐藏、关闭、失焦和切换便签前立即刷新待保存任务。
- 管理窗口与桌面窗口同时编辑同一便签时，服务端按请求到达顺序更新完整内容并生成新的 `updated_at`，即实体级最后写入者胜出。
- 收到外部更新事件时，无本地未保存修改的窗口立即刷新；存在本地修改时先完成本地保存，再按服务端最终版本刷新。

首期不实现协同编辑或逐块合并。这一限制通过短防抖、显式保存状态和实体级版本控制保持行为可预测。

### 5.2 锁定生命周期

1. 主进程停止接受新的便签写请求。
2. 向便签窗口请求刷新草稿，并设置短超时。
3. 无论刷新是否完成，隐藏所有便签窗口和管理窗口。
4. 清除渲染层便签正文和会话密钥。
5. 解锁后重新允许访问，并恢复本次会话锁定前可见的桌面便签。

锁定优先级高于保存。超时草稿只允许留在当前进程内存，禁止写入明文临时文件。

## 6. 备份、导入导出与同步

导出载荷升级版本并新增 `noteBooks` 与 `notes`。导出前由服务层解密，导出文件继续遵循现有敏感数据提示和保护流程。导入接受旧版本载荷；字段缺失时视为空便签集合。

同步包新增便签本、便签和删除墓碑。沿用现有实体级 LWW 策略，以 `updated_at` 选择较新记录。合并后：

- 丢失便签本引用的便签归入默认便签本。
- 软删除时间比活跃记录更新时间新时，保留删除状态。
- 窗口坐标在目标设备显示前重新校正。
- `is_desktop_visible` 不触发远端设备自动弹窗；同步后仅保留为本设备的显示偏好，避免另一台设备意外展示内容。

最后一条使桌面可见性属于设备本地状态。窗口几何和置顶也不参与跨设备同步，但可进入本机备份以便恢复。领域内容、颜色、收藏、所属便签本和删除状态参与同步。

## 7. 搜索

搜索由主进程在已解锁状态下完成，对解密后的标题和所有块文本进行匹配，并复用项目现有的中英文大小写与拼音搜索惯例。回收站只搜索已删除便签；其他视图排除已删除便签。

锁定状态不提供便签标题、摘要、数量或搜索结果，避免从未加密索引泄露内容。

## 8. 异常处理

- 自动保存失败时保留草稿，显示失败状态和重试操作；保存成功前阻止用户主动关闭该便签窗口，但锁定和应用强制退出仍可继续。
- 解密失败、块 JSON 损坏或版本不支持时不覆盖原始记录。管理窗口显示不可编辑的异常项，并允许导出不含密钥的诊断信息。
- 管理窗口或桌面窗口创建失败时显示全局错误提示，数据库内容保持不变。
- 保存的窗口位置失效时回退到当前主显示器的可见工作区。
- IPC 对 ID、颜色、块类型、块数量、文本长度、缩进和窗口尺寸做边界校验。
- 便签本删除、同步和导入使用事务，避免生成悬空引用。

- 经典/动森、浅色/深色和中英文界面均保持可读。

## 10. 实施边界

实现应优先复用现有窗口生命周期、主题 token、UI 组件、加密服务、备份格式与同步合并模式。不得将便签字段塞入 `password_entries`，不得在渲染层保存明文文件，也不得为了便签功能重构无关的密码库页面。
